# replace-me の変更で守る事情（プロファイル）

本リポジトリで作業するときに、どこを見れば何が決まっているかの索引です。規範の本文は各正本に置いたままにし、
ここへ複製しません。ブランチ・コミット・品質ゲートは `CLAUDE.md` と `.github/copilot-instructions.md`、
自律ループ実行モードでの進め方は Skill `autonomous-loop` が正本です。

## 1. 技術スタックとコマンドの所在

| 項目 | 内容 | 正本 |
| --- | --- | --- |
| 言語・フレームワーク | replace-me | replace-me |
| ビルド・テスト・lint のコマンド | `CLAUDE.md`「本リポジトリの品質ゲート定義」を参照（本スキルへ転記しない） | `CLAUDE.md` |
| コマンドを実行する前提（ツールの版、環境変数、作業ディレクトリ） | replace-me | replace-me |
| 生成物・キャッシュの置き場所（品質ゲートが素通りしていないかを見る場所） | replace-me | replace-me |

## 2. 実機・エミュレータでの検証

| 項目 | 内容 |
| --- | --- |
| 実機・エミュレータでの確認が要る変更 | replace-me（例 画面の表示、OS の権限、外部機器との通信） |
| 検証の手順を定めたスキル・文書 | replace-me（無ければ「なし」） |
| エージェントが確認できない項目の扱い | BACKLOG へ `区分: 人手検証` で起票する（記述は `docs/records/spec/FORMAT.md`） |

## 3. 固有の運用

規定ブランチ・レビュー責任者・自律ループ実行モードの採否は `CONTRIBUTING.local.md` に書き、ここへは書きません。

| 運用 | 守ること | 正本 |
| --- | --- | --- |
| replace-me（例 文言の置き場所、二重管理しているファイルの同時更新、版ごとの差） | replace-me | replace-me |

## 4. 差分レビューで見る固有の観点

`diff-reviewer` が共通の観点に加えて見る、本リポジトリ固有の観点です。

| 観点 | 見ること | 正本 |
| --- | --- | --- |
| replace-me（例 権限・プライバシー、公開する文言、互換性） | replace-me | replace-me |

## 5. 配布元から取り込まない資産

配布元の資産のうち、本リポジトリで採用しないもの・固有の内容で置き換えているものと、その理由です。
取り込みのたびに上書き・追加しないよう、ここで確かめます（取り込みの区分は `docs/guidelines/ADOPTION.md`「3. 適用方式」）。

| 資産 | 扱い | 理由 |
| --- | --- | --- |
| replace-me（例 `.claude/skills/<名前>/`） | replace-me（例 取り込まない / 固有の内容とマージする） | replace-me |
